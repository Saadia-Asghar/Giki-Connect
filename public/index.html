    How to use GIKI-Connect

    This page is your quick manual: what the project proves in the notebook, what the web app demonstrates, and how to click through without overstating the model.

    Tap a heading below to expand or collapse a section.

    What you are showing (proposal)
    • Social siloing — small circles tied to faculty / province / batch on a residential campus.
    • Society bridge — societies and hobby mixers as the realistic way out of those bubbles.
    • Interest tribes — K-Means groups students by shared interests + society + comfort + silo, not by “who looks like you” on demographics alone.
    What the model actually uses

    Every “Find my interest tribe” request builds a vector of 17 features saved from GIKI_Connect_Notebook.ipynb:

    • 14 hobby flags (checkboxes on the Student tab)
    • Society hours / week (set to 0 automatically if you pick “Not a member”)
    • Comfort (1–5 slider)
    • Silo index — from your % same-province / same-faculty friends + friend count, using the same formula as the notebook (p + f − p×f on the proportions).

    Not used for the tribe label today: faculty, year, and the society chips you pick. They are honest extras for your survey story; the API echoes them back as submitted but they do not enter kmeans.predict.

    Student tab — step by step
    1. Read the live stats (cohort size, K, feature count, PCA %) — they come from GET /api/meta and your files on disk.
    2. Skim Project context for limits and pilot wording.
    3. Fill Academic profile (optional for the model, useful for your report).
    4. Set Social connectivity sliders; pick Society involvement (hours + society chips if you are a member); tick hobbies.
    5. Scroll to The 4 interest tribes to see how the cohort splits before you run yourself.
    6. Click Find my interest tribe — you get a Tribe ID pill, explainable “how chosen” notes, the four-card map with yours outlined, plus events and anonymized peer ideas.
    GIKI admin tab

    Use the default token unless you changed GIKI_ADMIN_TOKEN. Post title, time, place, hobby tags, and optionally target tribes (0–3) so the right students see the event first in their list. Events save to data/events.json locally (or /tmp on Vercel).

    Notebook vs app

    Notebook: Chi-square, Pearson, EDA plots, elbow, K-Means fit, exports to output/model/ and combined_with_clusters.csv. App: loads those pickles and CSV, runs one prediction per form submit, layers event + peer rules on top—no retraining in the browser.

    Interest tribes (for event targeting)

    Each card is one interest tribe (Tribe ID 0–3) from the K-Means layer in the notebook. Optional target tribes prioritise those students; hobby tags alone still work for matching.
